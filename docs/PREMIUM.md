# Premium upgrade list

The 0.9.0 build is already a credible premium app: 12 mood portraits across window,
tray and Dock; encrypted local history with a Keychain key and passphrase lock;
approval-gated tools with an audit log; Quick Ask on Option+Space; full EN/RU/AR; a
lazy-loaded settings shell; and enforced budgets (767 ms cold start, 597 MB idle,
zero long tasks in a 320-token stream). This list is what to do next to justify a
price, ordered by what a buyer notices first.

Effort: **S** ≈ a day, **M** ≈ a week, **L** ≈ two weeks or more (one developer).
Every item names the evidence that proves it, because "premium" that cannot be
shown is just a claim.

Row 26 also asks for safe mode and crash-safe stream resume. Both are built. Safe mode
is built: a
launch asks for it with `--safe-mode`, with `OPENMONKEY_SAFE_MODE=1`, or from Settings →
Privacy → Diagnostics, and the app also asks for it by itself after two starts that died
before the app could mark itself running. Such a launch comes up without the model,
without the MCP servers and without the update check, the banner at the top of the app
says exactly that and offers a restart the ordinary way, and the count of launches that
died is kept in the profile folder and wiped by a launch that comes up. The chat is still
there — safe mode does not take the history away. Crash-safe stream resume is built too:
the answer is written to the disk while the model is still writing it, so a crash or a
quit leaves the part that was written behind, marked as unfinished, and it carries a
**Continue** button that asks the model to pick the thread up where it stopped. The part
already written is kept, the new text grows on the same row rather than becoming a second
answer, and the turn the model left off in is put back in front of it so it does not
write the whole thing again. A model that starts the answer over anyway has that repeat
taken off; one that only resembles what is written is left alone rather than cut in the
wrong place. An answer the user stopped is recorded as stopped and is not offered for a
carry-on — only an answer the app lost is. 6 unit tests on the repeat, 7 integration
tests on the agent and the row on disk, and one e2e spec that reads the button in the
page.

The publisher is built as well, and it is the one thing this app cannot take back, so
it is built around that. The agent can post to the user's own Telegram channel, Reddit
account, Bluesky account or Mastodon account, and nothing else: the target comes from
Settings rather than from the model, so the model cannot post to a channel the user did
not name. Every post stops for approval and is written to the audit log. The secret for
each channel lives in the macOS keychain and never in the settings file — the Telegram
bot token, the Reddit script app and account password, the Bluesky app password, the
Mastodon access token — and the page shows only the last four characters of the
identifying field, so a token cannot be read off the screen or out of a log. The app
keeps itself slow, because a channel that answers every few minutes reads as a bot:
ten posts an hour on Telegram, two on Reddit, ten on Bluesky, five on Mastodon, a
quarter of an hour between Reddit posts and a minute between Mastodon ones, and the
count survives a restart. A post that asks for upvotes, comments or follows is refused
before it leaves the Mac, since that is what gets an account removed. Bluesky and
Mastodon each carry a picture: the app fetches it itself, uploads it first, and writes
the post pointing at it — and a picture address on the local network is refused before
anything is fetched, so the app cannot be talked into reading the machine it runs on.
The platforms' own limits are the app's: 300 characters a reader can see on Bluesky, so
an emoji counts as one rather than two, and 500 on Mastodon. A Bluesky sign-in that
belongs to another handle is refused, and a Mastodon instance has to be an https
address, because the token travels with every post. 23 integration tests (a Telegram

A post can also be queued for later, and the app sends it when its time comes: the same
exact text is shown and approved first, the app waits rather than pushes through the
quiet hours, the network switch and the per-channel caps, and Settings → Publishing
lists what is waiting with a Cancel on each one. Nothing is sent that the user did not
read first, and a post whose approval policy is Block is refused.

A post can also be written down instead of sent. The agent drafts it and stops there;
it waits in Settings → Publishing, where the user reads it, edits the wording and then
sends it or queues it, and the wording the user leaves is the wording that goes out.
Sending from that page runs the post through the same machinery as any other post, so it
lands in the task rail and in the audit log and the hourly cap, the gap between two
posts, the network switch and the approval policy all still hold. A draft that asks for
votes is refused before it is written down; a draft that will not fit the channel is
written down and says so. The draft text is sealed in the encrypted database, and a
draft is removed only when the send or the queueing worked, so a failed send never loses
what the user wrote.

Row 23 also asks for delta downloads. They are not possible while the archive keeps one
name for every version, and that name is exactly what makes
`…/releases/latest/download/OpenMonkey-arm64.dmg` a link the site can hard-code and a
bookmark can keep. The blockmap of the build that is running and the blockmap of the
release on offer are then the same file, and a patch built from them would not be the
release — it would be a corrupted install. The updater therefore turns the differential
download off explicitly, so the whole archive is fetched: slower, and honest about what
it is. Delta downloads become possible the day the artifact name carries the version
(`OpenMonkey-0.9.2-arm64.zip`), and that change would cost the permanent download
link, so it is not made here.

## Do not rebuild

These are already the premium signal and should be protected, not replaced: the
12-mood portrait system wired to window, tray and Dock; AES-256-GCM history with a
Keychain key, scrypt lock and auto-lock; per-tool approvals, "remember for session"
and the audit log; Quick Ask with inline approvals; full EN/RU/AR with a real a11y
audit; the lazy settings chunk; the perf budgets and their tests. Any new feature
must keep the zero-telemetry, zero-network-by-default promise, and every list item
above needs a test, a capture, or a recorded number before it is called done.
